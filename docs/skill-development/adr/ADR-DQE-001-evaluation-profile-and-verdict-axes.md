# ADR-DQE-001 — Evaluation profile, verdict axes, and lifecycle-vs-claim status

- **Status:** PROPOSED (target contract). The **test corpus** is being aligned to this ADR now
  (dataset_version 4). The **skill** (`documentation-quality-evaluator`) is **NOT** changed in this
  round — implementing this contract in `SKILL.md` / `hard-fail.md` / `frontmatter_check.py` is deferred
  to a separately-approved v0.4 skill pass. Until then the skill keeps its v0.3 behavior and stays
  `experimental, manual-orchestrator-only, terminal_gate_authority: false, auto_trigger: false`.
- **Deciders:** corpus owner (user) + this session (test upgrade).
- **Context:** the 2026-07-31 blind matrix + §4X re-check found that several failures stem from *undefined
  evaluator contract* (defect-ledger D-06/D-10/D-11), not just from skill logic. Before any hard gate is
  changed, the input/output contract must be pinned so fixtures and reviewers have a stable target.

## Decision 1 — Explicit `evaluation_profile` input (D-06)

DQE must receive an explicit profile rather than inferring provenance/decision context. Every corpus
`manifest.yaml` already carries `profile`; this ADR promotes it to the authoritative evaluator input:

```yaml
target: path/to/document.md
evaluation_profile:
  artifact_type: adr | roadmap | architecture-doc | technical-proposal | experiment-report | evidence-matrix | ...
  provenance_policy: controlled | legacy | external
  decision_mode: release-gate | audit
  evidence_requirement: full | key-claims | labeled-only | none
  reader_profile: adr-comprehension | roadmap-execution | proposal-execution | reproducibility-execution | ...
  output_mode: gate | audit
```

### `provenance_policy` semantics (drives HF-9 severity — defect D-01)

| policy | applies to | rule for MISSING local traceability front-matter |
|---|---|---|
| `controlled` | docs generated by this Skills system / declared to follow local conventions / release-or-merge gating | **HF-9 = BLOCKER** (as today) |
| `legacy` | historical workspace docs not yet migrated; refactor inputs | HF-9 = **MAJOR migration finding** (not a blocker) unless the caller explicitly asks for a controlled gate |
| `external` | GitHub upstream docs, paper appendices, external RFC/PEP/KEP/ADR standards | HF-9 = **MINOR or N/A** — **must NOT FAIL on HF-9 alone** |

A checker stays profile-agnostic (raw finding) and the evaluator maps severity by policy. Recommended
checker shape (for the deferred skill change):

```json
{ "check": "traceability-frontmatter", "finding": "missing", "profile_required": true,
  "raw_status": "ABSENT", "final_gate": "UNDECIDED" }
```

→ evaluator: `controlled → HF-9 BLOCKER · legacy → MAJOR · external → MINOR/NA`.

## Decision 2 — Split document lifecycle from claim status (D-11)

Retire the overloaded `status: DECIDED` document header. Use two distinct vocabularies:

```yaml
# document-level (frontmatter): is the DOCUMENT itself a draft / in review / accepted / deprecated
document_lifecycle: DRAFT | IN_REVIEW | ACCEPTED | DEPRECATED
```

```text
# claim/decision-level (body or register): the knowledge state of a SPECIFIC assertion
FACT · VERIFIED · DECIDED · BASELINE · HYPOTHESIS · CANDIDATE · OPEN · DEFERRED · REJECTED · STALE
```

Rules:
- `document_lifecycle` describes the document; claim status describes an assertion inside it.
- An `ACCEPTED` evidence note **may** contain a `HYPOTHESIS` — "the document is accepted" ≠ "every claim
  in it is verified". (This is exactly why BP-005-pass must PASS.)
- The evaluator must not read a document-level `ACCEPTED`/`DECIDED` as a claim-level verification.

## Decision 3 — Two verdict axes; keep `DOCUMENT_QUALITY` as compat map (D-10)

Reported verdict (target output for the deferred skill change; **reviewers already emit the first two**):

```text
QUALITY_BAND   = PASS | PARTIAL | FAIL          # holistic document quality
GATE_DECISION  = ALLOW | BLOCK | INCOMPLETE     # may this proceed in the current workflow
FACTUAL_VALIDITY = VERIFIED | PARTIALLY_VERIFIED | UNVERIFIED
READER_TEST    = PASS | FAIL
CHECKER_STATUS = COMPLETE | PARTIAL | NOT_RUN
BLOCKERS       = [...]                          # the issues forcing BLOCK
```

Backward compatibility (so existing `score_grading.py` / `aggregate_eval_results.py` keep working):

```text
DOCUMENT_QUALITY = compat-map(GATE_DECISION):  ALLOW -> PASS ; BLOCK -> FAIL ; INCOMPLETE -> INCOMPLETE_EVALUATION
```

Example — a mostly-good doc with one blocking gap:

```text
QUALITY_BAND=PARTIAL · GATE_DECISION=BLOCK · BLOCKERS=[HF-15]   (=> DOCUMENT_QUALITY=FAIL)
```

Corpus impact THIS round: manifests gain **additive** `expected.quality_band` + `expected.gate_decision`;
`expected.document_quality` is retained as the compat mapping so no scorer needs rewriting.

## Decision 4 — Experiment reproducibility is evaluated by dedicated findings, not (only) HF-12A

Reproducibility of an experiment report is a distinct concern from "a bare load-bearing claim with no
handle" (HF-12A). It is evaluated via dedicated `required_findings`:

```yaml
required_findings: [missing-code-version, missing-environment, missing-execution-entry, missing-reproduction-tolerance]
```

Whether reproducibility deserves its own **hard gate** (e.g. HF-REPRO) is **OPEN** — deferred to the
skill round, decided only if the clean `GN-EXP-REPRO-001` fixture shows v0.3 cannot flag it via existing
gates. This ADR only fixes that the *corpus* separates "bare claim" (`GN-EVIDENCE-BARE-CLAIM-001`, pure
HF-12A) from "not reproducible" (`GN-EXP-REPRO-001`, findings-based).

## Decision 5 — Hard-gate tightening targets (for the deferred skill round; recorded here as contract)

Recorded so the corpus can encode the intended behavior as `forbidden_blockers` regressions now:

- **HF-13** fires only with: ≥2 formal artifact roles · distinct canonical sources · distinct natural
  update frequencies · both body-level primary content · no clear appendix/link subordination · observable
  harm (duplication / drift / contradiction / unclear ownership / reader cannot identify the canonical
  doc). Explicitly does NOT fire on: an architecture doc with one maturity snapshot; a roadmap with a
  10–20 line architecture summary; an ADR noting a few implementation consequences; an accepted doc with
  open questions; merely many/long sections.
- **HF-14a** fires only on two incompatible assertions about the **same state variable, same scope, same
  time** (e.g. "59 tests pass" vs "69 tests pass", both claimed current). Explicitly NOT: dangling TOC;
  removed section; missing metadata field; `document_lifecycle` vs claim status differing; a stable
  architecture with a non-blocking open question; a historical snapshot next to a clearly-dated current
  value. Dangling TOC ⇒ **link/navigation integrity**, not state contradiction.

## Consequences

- **Now (corpus):** fixtures adopt `document_lifecycle`; manifests carry two-axis expectations + the
  HF-13/HF-14a tightening encoded as `forbidden_blockers`; reviewers emit `QUALITY_BAND` +
  `GATE_RECOMMENDATION`.
- **Later (skill, separately approved):** implement profile-gated HF-9, two-axis output, HF-13/HF-14a
  tightening; then run the diagnostic matrix → full admission matrix.
- **Risk if skill lags corpus:** running the *unchanged* v0.3 skill against these fixtures will still show
  HF-9/HF-13/HF-14a mismatches — that is expected and is exactly the evidence the confirmatory spot-check
  captures (fixture-caused failures flip; skill-caused ones persist).
