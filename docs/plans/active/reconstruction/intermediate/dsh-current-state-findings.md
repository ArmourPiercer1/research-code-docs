### 3.1 Format (`.agents/notes/README.md`)

- Path encodes two axes: `{lifecycle}/{class}/yyyy-mm-dd-topic-title.md` (line 9).
- **Lifecycle = status**, top folder: `proposed/` (reviewed before implementation, not yet built), `implemented/` (shipped; "kept current with what actually shipped" — facts updated in place in the same change, lines 11-15), `rejected/` (considered and declined; kept only while it prevents a tempting mistake, else deleted as full triplet).
- **Class = kind of decision**, closed 6-set from `scripts/agent-note-tree.ts`: `feature`, `bug-fix`, `simplification`, `architecture`, `process`, `testing` (lines 21-34). `refactor` deliberately absent (overlaps `simplification`, line 34). Classification gate rejects other folders.
- Filename date = when first proposed (per git history) (line 17).
- Cross-references only as relative markdown links — "never bare prose or numbers" so they are mechanically checkable (line 17).
- **In-file format** (owned by `README.md` § The file format, gated by `verify-agent-note-format`): header `# Agent Note: <title>` + dateless `Status:` enum matching the folder (rejection reason as its only content); per-lifecycle body skeleton (`## Problem` opener everywhere; `Proposal`/`Acceptance criteria`/`Risks` in `proposed/`; present-tense `Decision`/`Consequences` with proposal-era headings banned in `implemented/`); **mandatory `Alternatives considered`**; `.zh.md` counterpart mirrors section-for-section with machine-checked header tokens in English verbatim (lines 100-125).
- Trilingual triplet: `foo.md` + `foo.zh.md` + `foo.i18n.yaml` (blob-hash pairing record).
- Current corpus size (English notes): **proposed 26, implemented 645, rejected 10, archived 171** (counted 2026-09-09).

### 3.2 Lifecycle transitions

- `proposed/` → `implemented/`: rewrite `## Proposal` into present-tense `## Decision`, fold acceptance criteria/risks into `## Consequences` (or present-tense Testing/Verification), drop plans — "the rewrite made mechanical" (README line 121). Format gate fails the move if the skeleton isn't re-satisfied.
- `proposed/` → `rejected/`: only add the reason to the `Status:` line; file frozen (line 121).
- **Supersession**: every new note triggers a scoped audit of active notes (README line 19 + `.agents/notes/AGENTS.md:5` + `dsh-archive-agent-notes` SKILL.md:16). Full supersession → consolidate unique rationale into the current owner, repair inbound links, delete old triplet in the same PR; partial → both stay cross-linked. Removal-of-a-feature note becomes owner only after complete absence from code/config/schemas/formats/migration/compat and no test exercises it as supported (`2026-07-19-require-agent-notes-for-non-trivial-changes.md:19`).
- **Archival** (`.agents/notes/archived/AGENTS.md` + `2026-07-26-frozen-agent-note-archive.md`): only implemented notes archive; complete triplet moves to `archived/{kind}/` (no `implemented` segment); only permitted edit is `Archived: YYYY-MM-DD` under both `Status: implemented` lines + sidecar re-record + inbound-link repair; then the triplet is **permanently frozen**, sealed by path + SHA-256 in an append-only manifest (`verify-archived-agent-notes`, `--write` first proves all existing seals match); root `.rgignore` excludes the archive from parent-directory search (`.rgignore:2`); all evolving doc gates (format, pairing, wrap, links, budgets, type-equiv) **exclude archive sources** so standards can't force edits to history (frozen-archive note:19-21).
- **Discovery**: no `INDEX.md` (removed; gate rejects a root INDEX — `2026-07-19-remove-generated-agent-note-index.md`); the lifecycle/class filesystem tree is the inventory; README is the curated entry point; search is the other discovery path.
- **Enforcement**: `verify-agent-note-format` (per-lifecycle skeleton, header, Status/folder agreement), `verify-agent-note-classification` (closed class/lifecycle set, legacy homes, no root INDEX), `verify-archived-agent-notes` (seals, triplets, kind folders, metadata), `verify-translation-pairing` (zh sidecar) — all in `doc-sync`/`doc-quick` (gate list §6). ## 7. Snapshot/replay infrastructure, pre-push and test selection

### 7.1 Recorded-session snapshot system

- **Tree**: top-level `snapshots/` with four owner trees — `session/` (headless one-shot), `sdk/` (persistent JSON-RPC control), `acp/` (automation protocol), `web/` (browser/ARIA beside the same session) — plus per-scenario dirs (e.g. `session/partial-landlock-child-failure/` postmortem pin, `agent-instructions/`, `ptc-workspace-context/`; scenario list examined: `advanced-toolchain`, `background-job-admission`, `bash-spill`, `compaction-recovery`, `empty-response-retry`, `error-finish`, `fs-delete-recreate`, …).
- **Manifest**: each scenario dir owns a closed `snapshot.yml` (scenario, shipped profile, composition/header class, recording source, only the facts the session cannot reconstruct) + `session.jsonl` + contiguous child logs + optional prompt/schema sidecars + optional `workspace/` seed + `workspace.expected/` oracle.
- **Kit**: `packages/test-support/session-snapshot` (README read in full): closed manifests, typed identity redaction (first-seen tokenization across parent/child logs), pure normalizers (paths → `{{cwd}}`, header bulk → `{{system}}`/`{{tools}}`, zeroed times), fixture guards (orphan dirs, missing files, multiple pins per header class, unscrubbed headers all fail the suite before comparisons), record/replay/refresh write-back, `posixOnly`/`pwshOnly` platform scenarios, ACP adapter drives a real subprocess over JSON-RPC stdio and fails closed on unhandled permission requests.
- **Model replay without keys**: `dsh-llm-replay` serves recorded streams; `DSH_SNAPSHOT=replay|record|refresh` selects mode (testing.md:16).
- **Semantics**: replay = read-only comparison (CI); record needs a key; refresh is keyless (rewrites stdout/session-log/sidecars from committed model scripts); every resulting diff reviewed. "Committed sessions are normalization fixed points" (`snapshots/AGENTS.md:9`); a mutating scenario's `workspace.expected/` is "an independent oracle which record and refresh never rewrite" (`snapshots/AGENTS.md:13`).
- **Problem solved** (as documented): keyless, deterministic proof of model-visible + durable + filesystem behavior for a non-deterministic LLM system; postmortem 0002 shows the second problem it protects against — a deterministic replay can prove the *regression* (fixtures refreshed to the failure) — hence `UNKNOWN_TOOL` rejection and header-class pins. Fresh-clone reliability is a secondary effect: `pnpm install && pnpm run test:snapshot` runs keyless on any OS with a shipped profile.

### 7.2 Pre-push and test selection

- **Hook side**: pre-push = incremental typecheck only (§6.1). The old full pre-push aggregate is **removed** — "do not recreate the removed `check:pre-push` aggregate" (`dsh-pre-push-checks/SKILL.md:68`); rationale in `2026-07-22-fast-local-git-hooks.md` (agents already run the tests; hooks add only cheap high-confidence defects; "a complete local rehearsal is reserved for an explicit request, CI diagnosis, or a repository-wide change", line 19).

Its test-selection machinery: `change-scope` report first (`scripts/change-scope.ts` — 248 lines; versioned JSON of committed paths vs resolved merge base + staged/unstaged/untracked; never guesses or fetches a base; exact ref resolution with `warnAmbiguousRefs`), then per-surface evidence selection (§2.1), then `vitest related <changed file>` dependency-graph discovery with named blind spots, then scoped `--coverage.include` keeping the 100% bar inside the selected scope (`SKILL.md:43-64`).
- **CI side**: the PR runs the full matrix regardless (§5.1) — the division of labor is explicit and repeated in three places (hook comment, fast-hooks note, pre-push skill): hooks = cheap local defects; agent-selected checks = behavioral evidence for the diff; CI = exhaustive coverage + platform matrix.

## 8. Stacked-PR and worktree integration practice (as documented)

1. **Standing order** (`AGENTS.md:131`): "Choose PR history deliberately. Split independent changes and fix the introducing PR before propagation. Standalone/stack branches may merge-forward or rebase. Rewrites use `--force-with-lease`, abort on remote movement, never raw `--force`; preserve an in-progress merge-forward checkpoint before taking a newer base."
2. **Ownership decision** (`implemented/process/2026-08-02-native-github-stacks-and-optional-rebases.md`): every same-repo chain of ≥2 dependent PRs must use GitHub's **official stack object** before landing; `PullRequest.stack`/`stackEntry.position` authoritative; same-author unstacked chains auto-linked bottom-to-top; mixed authors require user confirmation; cross-fork and missing-native-support hard-stop; "land the stack" = `gh stack merge <stack> --yes --merge` (all-or-nothing direct merge, or merge queue with every selected PR independently reaching `MERGED`); `gh stack sync` is the one exception to validate-before-publish (immediate post-sync validation, no merge until green). Problem solved: branch-base chains have no stack identity — no atomic landing, no trunk rules per layer, no retarget ownership (note:7-9).
3. **Landing skill** `dsh-merging-stacked-prs` (§2.1): the executable checklist of #2, plus branch deletion only after merged-state + zero dependent PRs on the branch.
4. **Review-on-stack cookbook** (`docs/cookbook/responding-to-pr-review-on-a-stack.md`): ground rules — **one worktree per PR branch** ("parallel fixes never share a checkout", line 9); fix lands on the PR that **introduced** the issue, then flows up-stack; each review fix a distinct commit; merge-forward or rebase deliberate, lease-protected; triage-verify-map-propagate procedure; **delegated-fix trust-but-verify** ("a sub-agent's report describes intent, not necessarily what landed… for a regression guard, prove it FAILS on the unfixed code", line 22); reply in-thread; re-audit after every rewritten push; land only through the official stack procedure.
5. **Supporting plumbing**: worktree-local lefthook (§7.3); `incremental-pr-base-retargeting` note owns the merge-forward checkpoint option; `dsh-pre-push-checks` owns the post-sync validation sequence; the GIF evidence skill stages **per worktree** (record the worktree's exact commit, build that tree, fresh scratch `DSH_HOME`/workspace/session per server, one storyboard = one evidence run, `record-browser-gif/SKILL.md:27-32`).
6. **What is NOT done**: no repo-side mechanical enforcement of stack membership (GitHub server state is the authority); no `gh`-independent stack tooling in `scripts/`; no in-repo worktree pool management — worktrees are per-branch checkouts managed by the agent/human.

## 9. Test-reliability guidance (flaky tests, quarantine, gates)

- **No quarantine directory, no retry-by-default**: the policy is *fix at the owner*, not suppress. `dsh-ci-test-reliability` bans masking: "Do not hide the failure in a snapshot normalizer, retry wrapper, broader timeout, global serialization setting, or weaker assertion" (`references/ci-flake-diagnosis.md:46`); the skill note records the deliberate decision against "a generic stress runner or regex gate immediately" and against broad textual policy (`2026-08-28-ci-test-reliability-skill.md:35`). The only retry in CI is the bounded **`retry: 2` for real-API e2e** where the external provider is the nondeterminism source (`e2e.yml:64-65`).
- **Self-skip discipline** (the keyless-stays-green design): real-API suites self-skip without keys — but two guards make self-skip honest: (a) `e2e.yml` preflight **hard-fails on a missing secret** so a skipped suite can't false-green (lines 15-18); (b) `sandbox.yml` legs grep the "N passed" summary so a self-skip on the proving platform is a failure (lines 39-41, 112-113).
- **Concurrent-execution contract**: specs run in forked workers beside other gate processes on shared hosts; "a spec that passes only when it runs alone is a defect in the spec" (`packages/AGENTS.md:18`, `scripts/AGENTS.md:5`, `docs/testing.md` execution model). Port/path/child-process ownership rules come from the reliability skill (§2.1).
