## Repository shape in one paragraph

DSH started as a Yarn-4 + dumble monorepo with vendored Cordis source and, within **one day** (2026-06-11), the entire quality-gate suite, the ADR/RFC decision corpus, lefthook hooks, and a CI matrix. It then spent three months in a steady state of: (a) shipping the harness (profiles, web GUI, Python SDK, subagents, Agent Teams), (b) **deleting** packages, APIs, and gates as the product surface sharpened, (c) moving rules from prose into scripts (`verify-*.ts`), and (d) archiving decision records. The pre-release stance is explicit in root `AGENTS.md`: "foundation over blast radius. Remove at the first tagged release."

## A.2 Fresh-clone CI failures

**What broke on fresh clones.** `fa91bbac54` 2026-06-11 "Fix CI: order steps by artifact dependency, resolve fresh-clone builds" (day one, ~12h after repo init) documents **three first-fresh-checkout failures "invisible locally because lib/ persists between runs"**: (1) Lint ran before Typecheck, but the type-aware ESLint config resolved vendor packages via built declarations (`vendor/*/lib`) that only Typecheck emits → 1,519 `no-unsafe-*` errors on every cross-package import; (2) the first-ever `tsc -b` resolved sibling vendor plugins through `package.json` types (`lib/index.d.ts`, not yet emitted) → TS2307 until a second run; (3) Hygiene ran publint (validates packed `lib/index.js`) before Build emitted them.

**What was built to prevent it.**
- Reordered CI steps; moved the source-level `paths` map from root `tsconfig.json` (dev-only) into `tsconfig.base.json` so the whole build graph resolves source-first (the source-plane/artifact-plane doctrine now in `AGENTS.md`).
- `AGENTS.md` documented the one fresh-clone case needing `yarn typecheck` before `yarn lint` (added same commit).
- 2026-06-17: `implemented/process/2026-06-17-ts-build-config.md` — tsconfig project layout made explicit.
- 2026-07-04: `implemented/process/2026-07-04-tsconfig-solution-root-two-aggregates.md`.
- 2026-07-21: `implemented/process/2026-07-21-serial-cross-platform-ci-reference.md` (`c86d85724d`) — master-only **serial standby lanes** run the complete aggregate serially on self-hosted pools as an independent completeness oracle ("a defect in [PR] gate inventory or dependency graph could omit work while the required aggregate stays green"); strict duration timeouts deliberately removed — "a latency regression is observed rather than automatically cancelled".
- 2026-07-23: `implemented/process/2026-07-23-portable-required-pull-request-ci.md` — required CI must run on portable (hosted) capacity.
- 2026-07-26: `implemented/process/2026-07-26-pnpm-action-setup-for-symmetric-ci-caching.md` (symmetric store/cache per runner) and `implemented/process/2026-07-26-ci-failover-runbook.md` — failover runbook incl. "clean bootstrap" (emergency-capacity runner clone excluding `.runner/.credentials`).
- `d606ab6877` 2026-07-27 "ci: standby archive base ref; runbook — dependabot exception, clean bootstrap, variable trust model" — standby lanes fetch depth 2 + `DSH_ARCHIVE_BASE_REF=github.event.before` so the frozen-archive comparison compares against the frozen archive instead of the new manifest against itself.
- 2026-07-30: `implemented/process/2026-07-30-independent-ci-consumer-build.md` (independent runner allocation for the consumer lane).
- 2026-08-08: `implemented/process/2026-08-08-native-windows-pull-request-ci.md` — dual-Windows decision: Wine job is the required portable check; independent native Windows job reports the complete inventory without joining the required aggregate.
- `61f910d1c6` 2026-08-19 "ci: split master-only jobs into ci-master.yml" (PR panel stopped listing grayed master-only jobs) + `e6b494ed17` (dead job removal).
- `12c161e1a7` 2026-08-27 "perf(infra): map each workspace package to an explicit path alias" (note `implemented/process/2026-08-27-explicit-workspace-path-aliases.md`) — kills resolution ambiguity at the cost of an alias table.

- 2026-08-31: zero-build coverage lane + gate fail-fast (see A.1).
